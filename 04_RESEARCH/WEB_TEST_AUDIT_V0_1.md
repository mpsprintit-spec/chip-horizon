# Web Test Audit V0.1 — STWF Visual Laboratory

**Date:** 2026-10-06  
**Status:** Corrective audit after manual web inspection  
**Scope:** STWF Visual Laboratory v0.4 → v0.5

## Finding

The v0.4 interface created a serious validation weakness:

1. The five state nodes in STATE mode were drawn at fixed spatial coordinates.
2. Their state values changed, but there was no explicit visual transport event showing information moving between nodes.
3. The computation test calculated both the expected and actual trajectory from the same recurrence: S = λS + X.
4. Therefore a PASS from that implementation was not sufficient evidence that the intended model implementation had been independently checked.
5. A user could not inspect the complete step-by-step evidence needed to decide whether the test was meaningful.

This is a **test-harness verification problem**, not evidence that the STWF concept itself is wrong.

## Corrective requirements

The web test must distinguish:

- **reference truth** — predefined expected values;
- **runtime result** — values generated by the implementation under test;
- **visual state** — what the browser actually renders;
- **physical interpretation** — what remains unverified until a measurable physical system exists.

The test must never claim a physical experiment result.

## v0.5 corrections

### 1. Fixed reference vector

The reference trajectory is explicitly fixed:

X = [3,5,2,7]

S = [3,8,10,17]

The reference values are not generated by the runtime test function.

### 2. Runtime trace

The test records, for every step:

- step number;
- input X_n;
- reference value;
- runtime value;
- error.

It reports RMS error and maximum absolute error.

### 3. Visible transport

STATE mode now renders moving transport markers along the state links and a feedback marker between FIELD STATE and the central state node.

This does **not** prove physical propagation. It makes the browser model's intended information-flow explicit and inspectable.

### 4. Determinism of the reference test

The reference computation uses fixed λ=1 and does not use the stochastic visual-model noise. This is intentional: the reference test verifies the numerical representation harness separately from the noisy visual dynamics.

## Interpretation

A PASS now means:

> The browser's runtime implementation of the specified numerical recurrence reproduced the fixed reference trajectory within the stated tolerance.

It does **not** mean:

- the physical state exists;
- the material performs the operation;
- the wave field performs the operation;
- the model is physically accurate;
- the future chip will work;
- STWF is faster or more energy efficient.

## Next verification layer

Before treating the web laboratory as a scientific validation tool, the next layers should be added:

1. deterministic model tests;
2. independent reference implementation or hand-derived reference cases;
3. parameter-boundary tests;
4. reset/replay test;
5. noise-on/noise-off comparison;
6. conservation/limit checks where mathematically applicable;
7. exported trace data so a third party can independently calculate the metrics.

The general principle is **verification before validation**: first verify that the software correctly implements the defined model; only then ask whether the model represents a physical system.

## Research classification

- **Observed:** v0.4 visual behavior and implementation structure.
- **Verified correction:** v0.5 fixed-reference computation trace and visible transport layer.
- **Mathematical:** S_(n+1)=λS_n+X_n.
- **Not demonstrated:** physical computation, material behavior, device performance, speed, energy advantage.
